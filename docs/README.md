# GameLauncher

**暴雪也不是每次下整包。**

Battle.net 和 Steam 一样，用的是**增量补丁（patch / 差量更新）**，不是每次把整个《魔兽》《暗黑》重新下一遍。你感觉「又在下东西」，其实是在下本次改动的文件差量。

### 暴雪大致在干什么

```
Launcher（Battle.net）
  → 问服务器：当前版本 / 文件清单 / 校验哈希
  → 和本地对比，只下有变化的文件（或二进制差量）
  → 替换对应文件后启动游戏
```

逻辑 DLL、地图、资源，**改了哪个下哪个**，没改的不动。所以能做到「大版本也只要下几百 MB～几 GB 增量」，而不是每次 50GB+。

PC 端游戏不用代码热更新，完全靠 Launcher 能力发布 Patch。

这和 HybridCLR **完全是两条路**：

| 路线 | 做法 | 典型场景 |
|------|------|----------|
| **Battle.net / Steam 式** | Launcher + 文件级/差量补丁 | PC 端、可整包分发 |
| **HybridCLR 式** | 运行时热更 C# 逻辑 | 手游、不能随意换包体 |

官服要对齐暴雪，走的是**第一条**，不需要 HybridCLR。

---

### 你要做的改造（其实不重）

**1. Launcher（必须有，官服入口）**

- 启动后调版本接口（你们 `game-core` 的 version-check 一类）
- 拉「最新文件清单 + 哈希」或「补丁列表」
- 对比本地 → 只下载变更文件
- 校验通过后启动游戏 exe

**2. 客户端打包方式（要配合）**

- 发布时打出「可按文件更新」的目录结构（不要一个巨大的不可拆压缩包当唯一载体）
- 资源继续用 Addressables/AB，地图等大块本来就适合增量
- 逻辑程序集可以整文件替换（.dll / 主程序），Launcher 负责换

**3. 服务端**

- 维护版本号 + 文件清单（或补丁包 URL）
- CDN 上放增量文件即可

客户端本身**不用为了热更去改架构**；主要是：

- 打包输出要「可补丁」
- Launcher 负责对比和下载

---

### 和你现状的对应

```
Steam 渠道：Steam 当 Launcher（差量更新已有）
官服渠道：你们自己的 Launcher 做同样的事
```

两边都可以：

- 大版本 = 下变更文件（地图 AB + 改过的程序集）
- 日常小改 = 更小增量
- 只有引擎大升级才接近「整包感」

**结论：要对齐暴雪 = 做好 Launcher 的差量/文件补丁**  
客户端主要是配合「按文件发布 + 可被替换」；改造重心在 Launcher 和发布管线，不在游戏内热更框架。
